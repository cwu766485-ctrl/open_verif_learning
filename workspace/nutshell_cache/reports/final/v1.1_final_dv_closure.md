Current checked coverage is 53/53 Functional and 37/37 Cross; the Evidence Gate passed for local SHA `416bb5e` with 69 checked runs.

The existing same-line dual-store tests compare both cores' data and MESI state and model conflicting same-address stores in observed Directory acceptance order. They establish behavior for those accepted histories; they do not assert global Sequential Consistency or arbitrary CPU response reordering. Hit-under-Miss tests check distinct transaction IDs, response payloads and backpressure. The existing CR07 test checks a remote Snoop completing during another line's pending miss. Reference details are in [full-system results](../../docs/dv/full_system_verification_results.md), [scenario plan](../../docs/dv/full_system_scenario_testplan.md), and the checked [coverage evidence](../full_system/full_system_coverage_closure.md).

The 280-environment stress summary records 58,958/58,958 CPU accepts/completions for the CPU-random campaign and 100,300/100,300 for mixed CPU/MMIO/APB/AXI. Reset and injected-error campaigns intentionally cancel accepted work, so their accept/completion counts differ. The regression does not record a per-core maximum wait-cycle bound, and no starvation-free guarantee is claimed. The frozen contract requires eventual external response readiness for progress; no independent fairness assumption or unbounded system-liveness proof was established.

Reset tests now exercise an accepted AW followed by at least three W handshakes and a real WREADY stall, and a separate reset observation after all eight W beats but before B completion. The latter checks reset cancellation, absence of stale CPU response and post-reset reads against the backing memory model's per-beat committed contents. This follows the shared synchronous reset/drain contract in `docs/cache.md`; it does not claim atomic persistence of a partially accepted burst. Existing tests also cover AW backpressure and reset recovery. A reset after an already accepted B completion is ordinary post-completion reset behavior, not cancellation of an active write.
