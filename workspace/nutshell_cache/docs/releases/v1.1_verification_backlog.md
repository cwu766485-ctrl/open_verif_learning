## Closure rules

1. Build scenarios from legal CPU/protocol traffic; do not seed internal DUT state.
2. Use Python/Toffee sequences with independent data and Directory checkers.
3. Record Feature → Testpoint → Stimulus → Checker → Coverage mapping; credit
   coverage only after the checker passes.
4. State fairness assumptions for bounded progress checks; do not describe a
   bounded pass as an unbounded liveness proof.
5. Keep malformed input/error injection separate from legal recovery tests.

The source-level coverage list and line ranges are maintained in the
[Coverage Gap Review](../coherence_coverage_gap_review.md). Python functional
and cross-coverage IDs are mapped in
[`python_coherence_map.json`](../../dv/coverage/python_coherence_map.json);
existing IDs were preserved and new RCV bins were appended. The focused
subsystem Python tests now live in separate feature modules and share one
`CoherenceEnv`, sequences, agents, monitor, scoreboard, and coverage collector.
The 2,600-line SV subsystem bench is split into task-focused include files and
remains a fast cross-check baseline. Error injection remains distinct from
legal recovery traffic. PPA, SRAM mapping, and STA are outside this backlog.
