# v1.1 Verification Backlog: Integrated Recovery Paths

This backlog tracks additional integrated recovery and concurrency checks. A
path listed here is a verification gap, not evidence of a functional RTL bug.
The v1.0.1 required legal subsystem path for a queued stale Upgrade is closed
by an independent Python/Toffee test and feature bin.

## Closure rules

1. Build scenarios from legal CPU/protocol traffic; do not seed internal DUT state.
2. Use Python/Toffee sequences with independent data and Directory checkers.
3. Record Feature → Testpoint → Stimulus → Checker → Coverage mapping; credit
   coverage only after the checker passes.
4. State fairness assumptions for bounded progress checks; do not describe a
   bounded pass as an unbounded liveness proof.
5. Keep malformed input/error injection separate from legal recovery tests.

The source-level coverage list and line ranges are maintained in the
[Coverage Gap Review](../coherence_coverage_gap_review.md). PPA, SRAM mapping,
and STA are outside this verification backlog.
