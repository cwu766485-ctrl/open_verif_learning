# Cache Coherence v1.0.1 Maintenance Candidate

**Status:** candidate for review; do not move or retag the frozen `release/v1.0`
reference. The `cache_coherence` branch remains the development line.

## Scope

- Add a deterministic Python/Toffee nine-line L2 victim prelude covering a
  dirty M owner and a two-core S sharer victim. Verify accepted snoops, all
  owner-data beats, writeback response, and preserved data.
- Add an independent four-way L1 replacement check comparing the predicted
  victim line and MESI Put opcode with the accepted Directory request.
- Correct the reference model's L2 replacement pointer update on accepted
  PutM / full-line owner-data writes; add dedicated coverage bins and update
  the verification matrix.
- Record current formal, regression, coverage, and product-top lint results in
  the final verification report. No RTL datapath optimization is included in
  this maintenance slice.

## Known limit before calling the stress plan fully closed

An extra randomized experiment put nine lines in one L2 set and mixed
dual-lane traffic with backpressure. Fourteen of twenty seeds reported a
Directory model mismatch or CPU response timeout/protocol error. The accepted
stress sweep uses a less concentrated random pool and retains deterministic
nine-line dirty/shared L2 victim checks. The dense same-set concurrent case
remains unresolved and must not be represented as passing.

The integrated SystemVerilog testbench still emits categorized bench-only
warnings for optional monitor ports, width conversions, indentation,
timescale, unused test signals, test-model multiple drivers, and a deliberate
hierarchical `force` of `line_wr_ready` used for backpressure injection. These
do not appear in standalone product-top lint; no global warning waiver was
added.

PPA, physical SRAM mapping, and timing signoff are not part of this candidate.
GitHub Actions must show both `Legacy Cache Regression` and `coherence` green
on the final commit before tagging or publishing v1.0.1.
