## RTL conditions reviewed

`DualL1MesiCluster.sv` admits a secondary MSHR only when the primary slot is
active, exactly one slot is occupied, the secondary slot is free, the second
request needs coherence, and the request is neither a same-line nor same-set
request. It also requires the replacement FSM to be idle, no active/accepted
snoop, and the secondary context to be idle. A second request that needs a
victim is therefore held at the CPU interface until it can be looked up and
replayed safely.

Resident read Hit-under-Miss is enabled only at occupancy one, with the primary
context active, a free secondary slot, an L1 lookup hit, no replacement or
snoop, and a free/accepted hit-response slot. At occupancy two it is
intentionally backpressured. The response snapshot slot and two-context ID
reservation are not currently specified for a hit while both miss contexts are
live.

The per-core replacement FSM is single-owner. Its dirty-victim path performs
PutM, waits for transfer ownership, streams the victim line, and waits for the
completion/commit sequence before replay. Because secondary admission requires
replacement idle and a non-replacement request, a replacement PutM cannot be
started by a newly accepted secondary request while two contexts are live.
This is a serialization constraint, not evidence of a deadlock. The existing
remote owner-data Snoop test exercises snoop progress while two other misses
are live; the existing PutM/Snoop race test exercises the eviction boundary.

No unconditional liveness claim is made: progress depends on downstream
Directory/AXI responses, Snoop response, and CPU response readiness eventually
being granted. Removing admission guards would require explicit ownership for
the victim snapshot, array read/write arbitration, response slots, and a proof
that same-set replacement and Snoop cannot form a resource cycle.

## Design improvement proposal

1. Keep the current admission rules unless a directed test demonstrates a
   functional defect. Do not weaken `valid/ready` to increase concurrency.
2. Make the serialization points observable and regression checked: same-set
   replay, full-bank resident-hit stall, dirty PutM completion, and owner-data
   Snoop overlap.
3. Preserve per-core miss response order and the existing CPU interface. Do
   not add request IDs; these tests use the existing internal transaction IDs
   and verify they are unique while live and correctly reused after retirement.
4. Any later relaxation must reserve all required resources atomically before
   acknowledging the request, and retain the current MESI/Directory commit
   ordering. First candidate optimization is an explicit victim-context
   reservation, only if benchmark evidence shows the serialization is a
   material bottleneck.

## Formal properties to target

- No duplicate live transaction IDs within one routing domain.
- Every accepted MSHR entry remains stable until a legal state transition or
  reset cancellation.
- A completed CPU miss corresponds to exactly one accepted request and the
  correct address/data; same-core miss responses preserve acceptance order.
- No MSHR retires before its CPU response handshake or reset cancellation.
- Under explicit fairness assumptions (eventual grant/AXI response, eventual
  CPU response ready, and eventual Snoop response), every accepted miss
  completes within the declared bound. Without these fairness assumptions,
  progress is not guaranteed and the property must not be reported as proven.

## Exit criteria for an RTL change

Only change product RTL if one of the above legal directed scenarios fails or
an independently reviewed safety/progress property exposes a defect. Before a
change, save the failing seed/trace and identify the exact resource wait cycle.
After the smallest fix, rerun the focused test, coherence regression, full
system regression, Formal, mutation, and coverage audit on the same source
snapshot. A passing test that confirms intentional backpressure is not a
functional failure and does not justify removing the guard.
